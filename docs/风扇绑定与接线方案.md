# 风扇接线与温控绑定方案

> 机型：MSI MPG Z490 GAMING CARBON WIFI（M7C73）· 芯片 NCT6687-R · fnOS trim
> 应用：fn-fan-control 0.1.9 · 实测日期：2026-10-13
> ⚠️ 本文所有转速、占空比、失速点均为**真机实测**，非纸面推算。

---

## 一、接线与通道映射（实测锁定）

| 主板接口 | 风扇 | 数量 | 线型 | 实测满速 | 对应通道 | 实测依据 |
|---|---|---|---|---|---|---|
| CPU_FAN1 | A6x25 | 1 | 4pin | 3007 rpm | `hwmon6_pwm1` | 匹配 A6x25 上限约 3000 |
| SYS_FAN1 | A8x25 | 1 | 4pin | 2404 rpm | `hwmon6_pwm3` | 80mm 转速量级 |
| SYS_FAN2 | A8x25 | 1 | 4pin | 2307 rpm | `hwmon6_pwm4` | 80mm 转速量级 |
| SYS_FAN3 | M.2 散热扇 | 1 | **3pin** | 转速不报 | `hwmon6_pwm5` | 唯一零转速的**在用**接口 |
| SYS_FAN4 | B6015 | 4（GPU 散热片 ×3 + LSI 3008 ×1） | 4pin | **5128 rpm** | `hwmon6_pwm6` | 5128 rpm 只可能是 60×15 薄扇 |
| SYS_FAN5 | A12x25 | 2（一分二） | 4pin | 2094 rpm | `hwmon6_pwm7` | 匹配 A12x25 上限约 2000 |
| SYS_FAN6 | A8x25 | 1 | 4pin | 2316 rpm | `hwmon6_pwm8` | 80mm 转速量级 |
| PUMP_FAN1 | — | 0 | — | 0 | `hwmon6_pwm2` | 唯一空置接口 |

**映射方法（可复现）**：对 8 个通道依次设 100% 与 51% 占空比，记录转速差。有转速的通道 6 个 + 无转速但在用的 1 个（3pin M.2）= 7 个在用接口，与你描述的接线数量**完全一致**；再用满速量级区分 60/80/120mm 型号，四组各归其位。

> 注意：通道号与主板丝印**不保证同序**，本表由实测确定。换风扇或重插线后建议复测。

## 二、温控绑定（已应用到应用，可直接使用）

| 通道 | 显示名 | 温度源 | 曲线（温度 → 占空比） | 最低占空比 | 传感器失效安全值 |
|---|---|---|---|---|---|
| `pwm1` | CPU 风扇 A6x25 | CPU Package（coretemp） | 45℃→30% ｜ 60→50 ｜ 72→75 ｜ 85→100% | 30% | 80% |
| `pwm3` | 上层进风 A8x25 | 主板 System 热敏 | 38℃→40% ｜ 45→50 ｜ 52→75 ｜ 60→100% | **40%** | 70% |
| `pwm4` | 上层进风 A8x25 | 主板 System 热敏 | 同上 | **40%** | 70% |
| `pwm8` | 上层进风 A8x25 | 主板 System 热敏 | 同上 | **40%** | 70% |
| `pwm6` | GPU+HBA 4×B6015 | GPU 温度（nvidia-smi） | 40℃→30% ｜ 55→50 ｜ 68→75 ｜ 78→100% | 30% | 80% |
| `pwm7` | 下层排风 2×A12x25 | **硬盘最高温（虚拟传感器）** | 38℃→35% ｜ 43→50 ｜ 48→75 ｜ 53→100% | 35% | 80% |
| `pwm5` | M.2 散热 3pin | 待定（见第五节） | 暂手动 50% | — | — |
| `pwm2` | 未使用 (PUMP_FAN1) | — | 无 | — | — |

### 设计要点

- **上下层分工按你的气流拓扑**：上层 3×A8x25 为**进风**，只服务主板/CPU/GPU 区 → 绑主板 System 热敏；下层 2×A12x25 为**排风**，是机械硬盘的散热主力 → 绑 `max_hdd`。
- **`max_hdd` 是本次新增的虚拟传感器**（0.1.9）：自动取全部硬盘中最热那块的温度，6 块盘增减自动适应。进风/排风扇跟随"最热盘"而不是某一块固定盘，避免单盘过热被平均掉。
- **A3000LP 与 LSI 3008 同挂 SYS_FAN4**：GPU 拆了涡轮扇变被动，靠这 4 把 B6015；HBA 与之共组，随 GPU 温度调速（HBA 温度不可读，见第三节 5）。

### 当前实测状态

```
CPU 35.0℃  → pwm1 30% →  896 rpm   (CPU 风扇)
System 35.5℃ → pwm3/4 38~40% → 973/1011 rpm  (上层进风)
GPU 34.0℃  → pwm6 30% → 1437 rpm   (4×B6015)
max_hdd 34.0℃ → pwm7 35% →  851 rpm   (下层排风)
```

## 三、实测发现的安全项（必读）

### 1. SYS_FAN6 那把 A8x25 低速会失速 ⚠️
实测：30% 占空比 → **转速 0（停转）**；38% → 898 rpm 才起转。同型号的 pwm3/pwm4 在 30% 正常——**同一型号不同个体，起转点也会差**。
**处置**：该组最低占空比统一抬到 40%（留余量）。换风扇后必须重测起转点。

### 2. SYS_FAN4 挂 4 把风扇 —— 电流临界
并联时总电流 = 单把 × 4。60×15 薄扇典型 0.10–0.25A → 合计 **0.4–1.0A**；MSI 多数 SYS_FAN 接口标称 **1A / 12W**（请以你手册 "Fan connector current" 一节为准）。
**建议**：SYS_FAN4 改用**带 SATA 供电的分线 hub**（风扇从电源取电，只从主板取 PWM 与测速信号）——既保护主板接口，四把转速也更一致。
另请确认你的"串联"接法是**并联**（每把扇都拿到 12V）；若真是电气串联，每把只分到 3V，会转得极慢且不均。

### 3. M.2 那把是 3pin —— 现在不可控
3pin 风扇没有 PWM 调速线，接在 PWM 模式接口上会**恒速满转**，应用写占空比无效。
**处置**：在 BIOS 把 **SYS_FAN3 设为 DC 模式**，之后应用才能以调压方式调速。
该通道转速上报为 0（无测速线），不影响调速，但无法用转速验证——用耳朵/眼睛确认。

### 4. A3000LP 已改被动散热（最需要保护的部件）
铜散热片完全依赖 SYS_FAN4 那 4 把 B6015。已设最低 30%、失效安全值 80%（传感器读取失败时自动拉到 80%）。
**建议**：这组不要用手动低占空比；转码/游戏负载下观察 GPU 温度是否稳定在 80℃ 以下。

### 5. LSI 3008 温度读不到
`mpt3sas` 驱动不提供 hwmon 接口，应用无法读 HBA 温度。它的 B6015 与 GPU 同组、随 GPU 温度走。
**若 HBA 长期高负载而 GPU 空闲**：可把 HBA 那把扇改接空置的 PUMP_FAN1，单独绑 `主板 PCIe x1` 热敏（应用里一改即可）。

## 四、需要在 BIOS 里做的设置

| 项目 | 设置 | 原因 |
|---|---|---|
| **SYS_FAN3** | **DC 模式** | 3pin 风扇唯一可调速的方式 |
| CPU_FAN1、SYS_FAN1/2/4/5/6 | PWM 模式 | 应用通过 PWM 调速 |
| Smart Fan（BIOS 自动曲线） | 可保留 | 应用写入时会自动切到手动模式（`pwm_enable=1`）并接管 |
| 风扇"起转/补偿"(Fan Kick) | 建议开启 | 与本文失速保护互补 |

## 五、待确认：M2_1 上是哪块盘？

三块 NVMe 目前**全部挂在 PCH 通道**（`00:1b.0` / `00:1c.6` / `00:1d.0`），无法从拓扑判断哪块在 M2_1：

| 盘 | 型号 | 当前温度 | 应用里的传感器 id |
|---|---|---|---|
| nvme0n1 | Fanxiang S500Pro 512G | 40.9℃ | `hwmon_hwmon1/temp1` |
| nvme1n1 | WD SN750 1TB（WDS100T3X0C） | 40.9℃ | `hwmon_hwmon3/temp1` |
| nvme2n1 | E2M2 64G | 34.9℃ | `hwmon_hwmon4/temp1` |

告诉我 M2_1 上是哪块，我把 `pwm5` 绑到**该盘自身的温度**（比板载热敏准得多，板载 M2_1 热敏现在读 23℃，几乎不反映 SSD 发热）。

## 六、如何验证与自测

1. **UI「🔎 识别」按钮**：点一下该通道降速 6 秒，看/听哪组风扇变慢 → 确认通道身份
2. **手动模式**：拖滑块，观察转速跟随
3. **曲线验证**：`curl http://<NAS>:8190/api/status | python3 -m json.tool`，核对"理论占空比 vs 实际 pwm"
4. **压力测试**：跑一次转码/校验，观察 GPU 组与排风组是否按曲线提速

## 八、热验证实测（2026-10-13 深夜 · ComfyUI 满载）

**方法**：应用内后台记录器每 5 秒采集一次，你手动跑 ComfyUI（真实 CUDA 负载）约 11 分钟。

| 指标 | 实测值 |
|---|---|
| GPU 利用率 | 100% 持续 |
| GPU 功耗 | 57–60 W |
| **GPU 温度** | **73 → 80 ℃，稳定在 78–80 ℃ 震荡** |
| 风扇占空比 | 60%（封顶，全程贴合）→ 2992–3030 rpm |
| **收敛性** | 前半均值 79.0 ℃ → 后半均值 78.3 ℃（Δ=**−0.7**）→ **已收敛，不再升温** |
| 峰值时刻 | 22:26:58 达 80 ℃，风扇 60% / 3015 rpm |

**结论**：60% 封顶在真实 CUDA 满载下**能够收敛**（温度不持续爬升），你的噪音限额可以满足散热需求。代价是贴在温度上限运行（峰值 80 ℃）。

**测试强度的说明**：ComfyUI 是**极端合成负载**（100% 利用率持续 10 分钟）。A3000 在本机的实际用途（转码/推理等）不会长期跑满 CUDA，因此真实工况下温度与转速都会明显低于本次实测——曲线大部分时间会工作在 30~50% 区间。

**改进方向（已评估，不实施）**：
- 空间限高 **15 mm**，无法使用 NF-A6x25（25 mm 厚）；同厚度可选 NF-A6x15，但价格较高
- 现有 4×B6015 在 60% 封顶下已满足散热且噪音可接受，**维持现状**
- 若将来夏季长期贴 85 ℃ 再评估

**两点仍需注意**：
1. **本次测试是开盖状态**（你在旁边听音）——合盖后风道改变，如遇长期高负载可再复核一次；
2. 夏季环境温度上升会抬高这个平衡点（每 +5 ℃ 环境约 +3~5 ℃ 核心温度）。

---


**为什么需要**：本机实测发现同型号风扇的起转点不一致（SYS_FAN6 那把在 30% 停转、38% 才起转）——若某把扇在曲线低点停转，它负责的硬件就静默失去风量。被动散热的 A3000LP 尤其危险。

**工作方式**（应用自动执行，无需配置）：

| 阶段 | 行为 |
|---|---|
| 判定 | 占空比 ≥16%（pwm 40）但连续 2 个周期转速为 0 → 判定失速 |
| 补转 | 自动抬到"失速目标 + 30"（上限 55%），并记住该通道的起转下限 |
| 稳定 | 学到的下限持续生效，避免"补转→回落→再失速"来回震荡 |
| 告警 | 日志 WARNING + 界面卡片显示"⚠ 检测到失速，已自动补转" |
| 自动停用 | 补转后仍连续 3 个周期无转速 → 判定该通道**无测速线/未接风扇**，自动停用保护（只记一条日志，不刷屏、不误报） |

**实测记录**：
```
21:46:54 风扇 hwmon6_pwm8 失速：目标 PWM=77 但转速为 0，补转至 107 并记住下限
         → 占空比 77→107，转速 0→1000 rpm，稳定保持
21:50:00 风扇 hwmon6_pwm2 补转后仍无转速 → 自动停用失速保护   (空置接口)
21:50:00 风扇 hwmon6_pwm5 补转后仍无转速 → 自动停用失速保护   (3pin 无测速)
```

**可关闭**：每个通道的 `stall_guard` 字段（界面/API 均可设），默认开启。学到下限存在内存中，重启应用即回到配置值。
